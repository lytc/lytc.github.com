06 / AI & engineering judgment

A second model. A human decision.

AI can produce a change quickly. Deciding whether that change should ship is a different piece of engineering. I built an internal workflow to make that decision more explicit and reviewable.

The problem

AI-assisted implementation adds another source of code to an existing development process. A plausible explanation from the implementing agent is not enough to establish correctness. Review needs to consider the actual change, the risk it introduces, and the evidence supporting it.

What I built

I designed and implemented a workflow that assigns review effort according to risk, asks a different model to challenge proposed changes, and keeps consequential decisions with a person. The workflow is used by colleagues in product development.

The important boundary is responsibility: an agent can propose an implementation or raise a finding. A person still needs to decide what the evidence means and whether to accept the change.

How I use it

Much of my recent implementation work is AI-assisted. I use agents to work through changes, use another model to challenge the result, inspect the diff, and run relevant checks. I remain responsible for the decisions I make and the changes I submit.

A second model is an additional review input, not proof that the first model is wrong or that the resulting code is safe. I want disagreements to lead back to the code, the requirements, and a checkable explanation.

What is established

There is a working internal implementation and evidence of colleagues using it on product changes. That establishes use; it does not establish a measured reduction in defects or review time. I do not claim a quantified improvement in either.
